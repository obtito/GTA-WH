# 网页流畅度优化

2026-10-08。本轮保留现有城市和地标几何、材质、道路、碰撞与樱花密度。

## 渲染

烘焙城市此前由两个覆盖整城的大网格组成，普通镜头和局部阴影相机很难剔除画面外部分。现按 2000 米地块分成 187 个网格，每块计算真实包围体，并共享原材质。三角形跨越地块边界时完整归入其中一个地块，包围体包含整个三角形，避免边缘缺面。

原始 89,746 栋建筑、1,311,294 个三角面及位置、法线、UV、归一化顶点颜色逐项校验不变。碰撞盒不变。静态地块不再每帧重新计算局部变换。

真实城市数据的视锥提交量测试（16:9，非浏览器 FPS 测量）：

| 相机 | 原城市三角面 | 优化后三角面 | 减少 | 可见城市绘制批次 |
|---|---:|---:|---:|---:|
| 开场 | 1,311,294 | 737,204 | 43.8% | 94 |
| 黄鹤楼 | 1,311,294 | 228,482 | 82.6% | 36 |
| 武大樱顶 | 1,311,294 | 437,670 | 66.6% | 60 |

相同测试中局部阴影相机提交量减少约 88–91%。750 米分块会形成 965 个网格，虽减少更多面数，但增加过多绘制调用，因此使用 2000 米的折中。

普通绿树实测 696 棵、约 8.7 万三角面；细分树批次收益不足，保留原 6 批，仅恢复实际包围球和视锥剔除。樱花结构、密度及 GPU 花瓣动画保留。

## 交互与动画

- 时间滑杆事件按渲染帧合并，只应用最新值；停止拖动 160 毫秒后更新环境反射，避免连续生成环境贴图。
- 后台页面停止动画循环，重新显示时丢弃隐藏期间的时间差，避免恢复瞬间角色跳动。
- 自适应分辨率使用真实帧时长；持续低帧率才降低分辨率，连续有余量 12 秒后小幅恢复，减少反复升降。
- 初次着色器编译在加载层退出前完成，降低第一次拖动镜头时的编译停顿。
- 行人使用各自独立的骨架。屏外暂停骨骼计算但继续更新位置；回到画面时补齐动作相位。250 米内逐帧，250–700 米按 15 Hz，更远按 6 Hz 更新骨骼。视锥边缘保留 32 米余量。
- 轻轨、轮渡预计算路线分段并复用采样对象；小地图在位置、朝向、模式、缩放、尺寸、打卡状态均不变时复用已有画面。

## 回归检查

```bash
node tools/city-spatial-check.mjs
node tools/actor-performance-check.mjs
node tools/frame-budget-check.mjs
node --experimental-vm-modules tools/check.mjs
```

城市测试包含完整三角面和属性比对、跨块几何包围体、材质共享及 WebGL 索引边界。角色测试包含 72,000 次屏外骨骼更新跳过、重新入镜相位、8,000 次车厢路线采样与小地图缓存失效。几何提交量下降不等同于相同比例的 FPS 增长，实际表现取决于视角、屏幕分辨率和设备负载。
